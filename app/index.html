Help / controls

Select a visible waypoint by clicking it, or choose it from the Waypoint list. Hidden waypoint layers cannot be selected.

Drag a visible waypoint to move it. The editor converts the dragged screen position back to the game's waypoint coordinates and records the edit when you release the pointer.

Right-click a visible waypoint in Waypoint mode to toggle its AI Turbo marker. This changes waypoint +2 bit 7 only; X/Y, Sequence and Link Delta are preserved.

Editor column sits to the right of the circuit. Zoom and Overlay opacity are followed by the editor modes in their working order: Backdrop, Foreground, Surface, Waypoints, Recovery, Race, MiniMap and Map.

Waypoint mode shows the waypoint editor and enables normal click/drag waypoint editing. Surface and Foreground modes hide the waypoint editor and show the drawing tools for the selected bitmap layer. Recovery shows the code-proven collision-recovery direction field and its limited editing controls. These modes are mutually exclusive.

Recovery editing uses the authentic 40×28 +3 byte grid (8×8 gameplay pixels per cell). Left mouse rotates anti-clockwise and right mouse clockwise; hold either button for continuous rotation. Grab group supports individual add/remove clicks and a left-drag marquee for selecting multiple cells. The optional 8×8 grid is drawn above the track and below the arrows for visual alignment checks. Undo and Revert +3 are local to this layer.

Magnified Area uses a 64×64-pixel source window. Click the magnifying-glass button, position the frame over the circuit, and the magnified window updates. The same drawing tools work directly inside it. Toggling the magnifying glass off clears the magnified window to black.

Drawing tools are icon radio-buttons for freehand, line, outlined or filled rectangle/square, outlined or filled ellipse/circle, and fill. Area to Paint is selected with radio-buttons. Brush size uses a 1–9 slider and brush shape is a Square/Circle toggle. Foreground also has a Hatched 1/1 pattern: one pixel on, one pixel off at a fixed frequency; increasing brush size enlarges the hatch area without enlarging the hatch pixels. Right-click uses the current tool and brush as the secondary paint action: in Foreground mode it always paints the opposite of the selected value (Foreground ↔ Clear); in Surface mode it always paints Normal.

Surface painting always works on the real 160×112 logical grid, so one brush unit remains exactly 2×2 game pixels. Foreground painting works at the original 320×256 single-pixel resolution.

Overlay colour wheels change editor display colours only. Foreground and each Surface class have independent colours; Recovery has separate arrow/grid display colours. These preferences do not modify game resource data.

Labels can show the physical route-local waypoint ID or the logical sequence value. Duplicate sequence labels are deliberate: multiple physical points can represent the same lap progress.

Sequence groups draw yellow joining lines between geographically adjacent visible waypoints on the same route carrying the same sequence value. They never join A, B and C to one another. Yellow means logical equivalence within that route, not a route/link.

AI Turbo markers add a white outer ring to visible waypoints whose +2 high bit is set. Static tracing proves this flag can make the AI generate a Turbo input when its Turbo-use timer permits it. Link deltas ≠ +6 draws cyan directional arrows only for route-local links whose signed byte displacement is not the ordinary +6, with the delta value shown beside the arrow.

Route A and B are alternative normal AI driving lines. Route C is the AI service route selected by service-request state; the exact naming of every service trigger remains under investigation.

Research interpretation

+1 is the 320×256 foreground/occlusion mask. The bitmap starts at byte 0; the four extra bytes in $2804 variants trail the bitmap.

+2 is a packed 2-bit surface map at 160×112 logical cells, covering the 320×224 gameplay area at 2×2 pixels per cell.

+3 is the code-proven 40×28 collision-recovery direction field, one angle byte per 8×8 gameplay cell. The traced race-physics consumer consults it when the corresponding +2 Surface lookup returns class 1 (Edge / collision). The byte is used directly as a 256-step circle value; no display phase or reverse option is part of the game data. On the circuit view $00/$40/$80/$C0 point right/up/left/down.

Stored six-byte waypoint records are complemented before race use: each runtime byte is the stored byte XOR $FF. The decoded record contains signed X, a logical sequence/progress value plus the AI Turbo high-bit marker, signed Y and a signed relative Link Delta.

The physical waypoint ID is not the lap order. Sequence (+2 & $7F) is the logical progress value and may legitimately be shared by several physical waypoints.

The Link Delta at +4.w is the code-proven explicit next-node pointer displacement. +6 is ordinary physical succession only because each waypoint record is six bytes.

The editor's default waypoint position uses the code-derived game coordinate projection. Manual mapping controls are retained above only for reverse-engineering comparison.
